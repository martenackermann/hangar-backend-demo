# Hangar API — conventions

Rules for everyone working in this repo, especially the parallel feature slices. When
something here conflicts with your habits, this file wins. If you need something it does
not allow (a shared-file change, a new dependency), **do not work around it**: describe the
request in your final report.

## 1. Golden rules

1. **Stay in your module.** A slice edits only `app/modules/<its_module>/` (including its
   `tests/`). Never edit `app/core/`, `app/main.py`, `app/api/`, `app/jobs/`,
   `pyproject.toml`, `uv.lock`, `conftest.py`, CI or Docker files.
2. **Register by convention, not by wiring.** Routers, models, jobs, event subscribers and
   seeders are found by auto-discovery (`app/core/discovery.py`). You never touch `main.py`.
3. **No new dependencies.** Everything slices need is already installed (see §17). If
   something is truly missing, request it.
4. **Fictional data only.** Acme IT Services, Globex Fleet AG, Initech Logistics, hubs
   Riverton/Hillford/Eastgate, `example.com` addresses. Run `_spec/BLOCKLIST.txt` over your
   files before finishing.
5. **Green before done:** `uv run ruff check`, `uv run ruff format --check`,
   `uv run pyright`, `uv run pytest app/modules/<module>`.

## 2. Repository layout

```
app/
  main.py              create_app() factory (mounts system routers + discovered modules)
  cli.py               `hangar` management CLI (click)
  core/                shared infrastructure — no domain logic
    config.py          Settings (env vars), get_settings()
    db.py              Base, IdMixin, TimestampMixin, str_enum(), SessionDep, commit(), on_commit()
    errors.py          RFC 9457 problem+json, ApiError & friends, problem_responses()
    pagination.py      Page[T], PageParamsDep, paginate(), sort_param(), search_clause()
    schemas.py         ApiModel (camelCase), JobAccepted, ActionIn, BulkActionIn, BulkResult
    security.py        JWT, password hashing, CurrentUserDep, require_permission()
    workflow.py        Workflow state-machine helper (transitions, guards, audit, events)
    events.py          in-process event bus, TransitionEvent, @on_transition
    audit.py           AuditRecord + pluggable sink
    storage.py         local file storage, upload checks, signed download URLs
    logging.py         structlog JSON logging
    discovery.py       module auto-discovery
  api/                 system routers: /health, /jobs/{id}, /files/{token}
  jobs/                procrastinate App (`job_app`), worker, schema bootstrap, system tasks
  modules/<name>/      feature modules (one per slice)
alembic/               migrations (generated by QA; slices do not add migrations)
tests/                 foundation tests
conftest.py            shared fixtures for all tests
```

## 3. Module layout

```
app/modules/<name>/
  __init__.py
  README.md          what the module owns
  models.py          SQLAlchemy models (imported automatically before create_all/Alembic)
  schemas.py         ApiModel request/response schemas
  workflows.py       StrEnum states/actions + Workflow definitions (if the module has lifecycles)
  service.py         business logic; the only place that writes; takes AsyncSession + actor
  router.py          `router = APIRouter(prefix="/<resources>", tags=["<resources>"])`
  jobs.py            `blueprint = procrastinate.Blueprint()` + tasks
  subscribers.py     @on_transition / @subscribe handlers reacting to other modules' events
  gateways.py        adapters to external systems (interface + fake), see §13
  mail/              mail templates (see §12)
  seed.py            `async def seed(session)` + optional `SEED_ORDER`
  tests/             test_*.py (+ optional conftest.py for module fixtures)
```

Files you do not need may be omitted. Split large files into sub-packages if you like
(`service/`, `routers/`) — only the names above are discovered. A `router.py` may
aggregate several routers: `router = APIRouter(); router.include_router(a); ...`.

Cross-module rules:
- You may import another module's `models` (for foreign keys/joins) and its documented
  public service functions (read-only helpers). Never call into another module to change
  its data; publish an event or call its public service function that exists for that.
- Side effects across modules (send a mail when a staging state changes, ...) go through
  events (§11), not direct imports.

## 4. Naming

| Thing | Convention | Example |
|---|---|---|
| Tables | snake_case, plural | `service_requests`, `tour_stops` |
| Columns | snake_case | `asset_tag`, `resume_date` |
| Constraints / indexes | automatic via `NAMING_CONVENTION` | `uq_assets_serial_number` |
| Enum values (DB + JSON) | lower snake_case strings | `appointment_booked` |
| JSON fields, query params | camelCase (automatic via `ApiModel` / `alias=`) | `assetTag`, `perPage` |
| URL paths | kebab-case, plural resources | `/service-requests/{id}/actions/{action}` |
| Permissions | `<resource>.<verb>` | `service_requests.read`, `imports.run` |
| Jobs | `<module>:<task>` (namespace added automatically) | `imports_master:run_import` |
| Schemas | `<Thing>Out`, `<Thing>Detail`, `<Thing>Create`, `<Thing>Update`, `<Thing>Filters` | `AssetOut` |
| operationId | `<tag>-<function_name>` (automatic) | `service-requests-list_service_requests` |

## 5. Models & database

- Inherit `Base` (+ `IdMixin` for a bigint identity `id`, + `TimestampMixin` for
  `created_at`/`updated_at`). Business numbers (`SR0012345`, asset tags, serials) are
  separate unique columns, never the primary key.
- States are `StrEnum`s stored with `str_enum(MyState)` (VARCHAR + CHECK, no native PG enum).
- `Mapped[datetime]` is `timestamptz` automatically; always use aware UTC datetimes
  (`datetime.now(UTC)`). Use `date` for calendar dates.
- `dict[str, Any]` / `list[Any]` map to JSONB.
- Relationships: set `lazy="raise"` (or `"selectin"`) — implicit lazy loading does not
  work in async code. Load explicitly with `selectinload(...)`.
- Sessions: inject `session: SessionDep`. Nothing is committed implicitly — write paths call
  `await commit(session)` (from `app.core.db`), which also runs `on_commit` callbacks.
  `expire_on_commit=False`, so returning ORM objects after commit is fine.
- `IntegrityError` becomes a 409 problem automatically; for nicer messages check first and
  raise `ConflictError` / `DomainValidationError` yourself.
- **Schema changes:** slices create tables with `uv run hangar db-reset --yes` (drop +
  `create_all`). Do not write Alembic migrations; QA generates the initial migration later.

## 6. Schemas

- Every request/response model extends `ApiModel` (camelCase aliases, accepts snake_case
  too, `from_attributes=True`). Fields are snake_case in Python.
- Every endpoint declares `response_model` (or a return annotation) — the OpenAPI document
  is the frontend contract.
- Updates use `PATCH` with a model whose fields are optional;
  apply `body.model_dump(exclude_unset=True, by_alias=False)`.
- Detail schemas of entities with a lifecycle include
  `available_actions: list[<Action>]` computed with
  `workflow.available_actions(entity, user)` — the frontend renders buttons from it.

## 7. List endpoints (filters, sort, pagination)

`GET /<resources>?page=1&perPage=25&sort=-createdAt,name&q=...&status=a&status=b`
returns `{ "data": [...], "meta": { "page", "perPage", "total", "totalPages" } }`.

```python
SORT = sort_param(
    {"createdAt": Asset.created_at, "serialNumber": Asset.serial_number},
    default="-createdAt",
    tiebreaker=Asset.id,  # deterministic paging
)


@router.get("", response_model=Page[AssetOut], responses=problem_responses(401, 403))
async def list_assets(
    session: SessionDep,
    _: Annotated[CurrentUser, Depends(require_permission("assets.read"))],
    paging: PageParamsDep,
    order: Annotated[list[OrderBy], Depends(SORT)],
    q: Annotated[str | None, Query(description="Search serial / asset tag")] = None,
    status: Annotated[list[AssetStatus] | None, Query()] = None,
    site_id: Annotated[int | None, Query(alias="siteId")] = None,
) -> Page[AssetOut]:
    stmt = select(Asset).order_by(*order)
    if (clause := search_clause(q, Asset.serial_number, Asset.asset_tag)) is not None:
        stmt = stmt.where(clause)
    if status:
        stmt = stmt.where(Asset.status.in_(status))
    if site_id is not None:
        stmt = stmt.where(Asset.site_id == site_id)
    return await paginate(session, stmt, paging, AssetOut)
```

- `perPage` max is 200 (422 above). Unknown sort keys → 422 `errors.sort`.
- Multi-value filters repeat the param (`?status=a&status=b`). Ranges use
  `<field>From` / `<field>To` (inclusive). Booleans `true`/`false`.
- Many filters? Put them in a `<Thing>Filters` dataclass dependency in your module.
- "Hidden by default" states (e.g. completed/cancelled) are excluded unless `status` is given
  or `includeClosed=true`.
- Exports (`GET /<resources>/export.xlsx` / `.csv`) accept the same filters (no paging).

## 8. Transitions (lifecycles)

- Define states/actions as `StrEnum` and one `Workflow` per lifecycle in `workflows.py`
  (see the docstring in `app/core/workflow.py` and `tests/test_workflow.py`).
- Single: `POST /<resources>/{id}/actions/{action}` — `action` is typed as the action enum
  (unknown → 422), body `ActionIn` (or a subclass with action-specific fields). Returns the
  updated detail (200). Errors: 403 permission, 409 `transition-not-allowed` (body has
  `currentState`, `allowedActions`), 422 field errors.
- Bulk: `POST /<resources>/bulk/{action}` with `BulkActionIn` (`ids`, max 500). Returns
  `BulkResult` (`succeeded: [ids]`, `failed: [{id, status, title, detail}]`), HTTP 200 even
  when some items fail; ids that do not exist are reported as 404 failures. Use
  `workflow.apply_bulk(...)`.
- Always go through `workflow.apply(entity, action, actor, session=session, comment=...)` —
  it checks permission + guards, sets the state, writes the audit record and publishes the
  `TransitionEvent`. Then `await commit(session)`.
- Jobs use `actor=None` (system), which skips permission checks but not guards.

## 9. Long-running work & jobs

- Anything slower than ~1 s (imports, mass mails, provider sync, PDF batches) runs in a job.
  The endpoint stores the input (e.g. the uploaded file + a batch row), commits, defers the
  task and returns **`202 JobAccepted`** (`{ "jobId", "statusUrl" }`). Clients poll
  `GET /api/v1/jobs/{jobId}` (`status`: todo/doing/succeeded/failed/…, `finished`).
- procrastinate stores no results: keep progress/results in your own table (e.g.
  `import_batches.processed_rows`, `report_file_key`) and expose them on your resource.
- `jobs.py`:
  ```python
  blueprint = Blueprint()


  @blueprint.task(name="run_import", queue="imports", retry=3)
  async def run_import(batch_id: int) -> None:
      async with get_sessionmaker()() as session:
          ...  # load by id, do work, commit(session)


  @blueprint.periodic(cron="0 6 * * *")
  @blueprint.task(name="daily_dispatch", queue="mail")
  async def daily_dispatch(timestamp: int) -> None: ...
  ```
  Task names are namespaced automatically (`imports_master:run_import`).
- Arguments are JSON scalars (ids, not objects). Tasks must be idempotent and open their own
  session via `get_sessionmaker()`.
- Defer *after* the data the job needs is committed: either commit then
  `await task.defer_async(...)`, or register `on_commit(session, lambda: task.defer_async(...))`.
- Queues: `default`, `mail`, `imports`, `sync`, `reports`, `maintenance`. Use
  `queueing_lock=` to avoid duplicate pending jobs (e.g. one sync per calendar).
- Run a worker locally: `uv run hangar worker` (or `uv run hangar-worker`).

## 10. Authentication & permissions

- `user: CurrentUserDep` → any authenticated user (401 otherwise).
- `_: Annotated[CurrentUser, Depends(require_permission("assets.update"))]` → 403 unless held.
  It returns the user, so use it instead of `CurrentUserDep` when you need both.
- Role → permission matrix lives in the core module (phase 2b). Permissions are dotted
  strings; `x.*` grants a namespace; admin has `*`.
- Row-level scoping (a technician only sees their own tours) is enforced in the service
  query, never only in the frontend.
- Every endpoint is authenticated except `/health`, `/files/{token}` (signed) and the auth
  endpoints.

## 11. Errors & events

- Raise `NotFoundError`, `ConflictError`, `PermissionDeniedError`, `DomainValidationError`
  (`{"fieldName": ["message"]}` with camelCase field paths), `TransitionError`, `GoneError`,
  or `ApiError(status=..., slug=..., title=...)`. All render as `application/problem+json`.
  Never return ad-hoc error bodies.
- Document error statuses with `responses=problem_responses(401, 403, 404, 409)`.
- Cross-module side effects: in `subscribers.py`
  ```python
  @on_transition("service_request", to_state="shipped")
  async def mail_shipping_confirmation(event: TransitionEvent, ctx: EventContext) -> None:
      on_commit(ctx["session"], lambda: send_shipping_mail.defer_async(sr_id=event.entity_id))
  ```
  Handlers run inline inside the publisher's transaction; keep them quick, defer the rest.

## 12. Mail

- Templates live in `app/modules/<name>/mail/`: `<template>.subject.txt`, `<template>.txt.j2`
  and `<template>.html.j2` (Jinja2, autoescaped HTML, English, fictional sender
  `MAIL_FROM`). Links use `FRONTEND_URL` / `APP_URL`.
- Mail is always sent from a job (queue `mail`) through the mail gateway provided by the
  core module (phase 2b), never directly from a request. Locally it lands in Mailpit
  (`http://localhost:8025`); in tests the fake gateway records messages.
- Recipients are `@example.com` only. Log mail sends (template, entity id), not bodies.

## 13. External systems (gateways)

- Booking provider, parcel carrier, ITSM data etc. are accessed through a small `Protocol`
  interface with a real HTTP adapter (`httpx.AsyncClient` + `tenacity` retries) and a
  **fake implementation that is bound by default** (`DEMO_MODE=true`). The core module
  (phase 2b) provides the shared gateway registry/dependencies; modules depend on the
  interface (`Depends(get_<x>_gateway)`), never on a concrete class.
- Tests use the fakes; test HTTP adapters with `respx`.

## 14. Files, PDFs, spreadsheets

- Uploads: `await storage.save_upload(file, allowed=CSV | XLSX, field="file", subdir="<module>")`
  (`storage: StorageDep`). Size/type problems become 422 on `field`. Persist the returned
  `StoredFile` metadata (key, original name, content type, size, sha256) on your model.
- Generated files: `storage.save_bytes(pdf_bytes, filename=..., content_type=..., subdir=...)`.
- Hand out downloads as `storage.signed_url(stored)` (relative, default TTL 15 min;
  `absolute=True` for mails). Authorize before creating the URL.
- Small, synchronous exports may stream directly
  (`Response(content, media_type=..., headers={"Content-Disposition": ...})`).
- Spreadsheets: polars (`read_csv`, `read_excel` via fastexcel, `write_excel` via
  xlsxwriter). PDFs: ReportLab (barcodes/QR via `reportlab.graphics.barcode`).

## 15. Seeds

- `seed.py`: `async def seed(session: AsyncSession) -> None` and optional `SEED_ORDER`
  (core = 10; others 100 by default). `uv run hangar seed` runs all seeders in one
  transaction.
- Seeds must be **idempotent** (do nothing if their data exists — Docker runs them on every
  start), deterministic (`Faker.seed(...)`, fixed dates relative to a fixed anchor or
  "today"), and use the fictional universe only. Demo password is the literal `demo1234`.

## 16. Tests

- Location: `app/modules/<name>/tests/test_*.py` (foundation tests in `tests/`).
- Async tests need no marker. Fixtures from the root `conftest.py`:
  `client` (httpx client against the app, DB session + storage overridden), `db_session`
  (rolled back after each test; `commit()` is safe), `auth_headers` / `make_token(sub, roles=...)`,
  `jobs` (in-memory procrastinate connector, autouse — inspect `jobs.jobs`, or run
  `await job_app.run_worker_async(wait=False, install_signal_handlers=False)`),
  `audit_sink`, `storage`, `app`.
- Each slice uses its own databases: set `TEST_DATABASE_URL` (e.g. `hangar_h3_test`) and
  `DATABASE_URL`/`PORT` in your `.env` (see WORKSPACE port table).
- Time-dependent logic: `time_machine.travel(...)`. HTTP adapters: `respx`.
- Cover: happy path, permission (401/403), validation (422 shape), transitions (409),
  pagination/sort, and job behaviour.
- Router modules that build dependencies in closures should avoid
  `from __future__ import annotations` (FastAPI resolves annotations at runtime).

## 19. Logging

`log = structlog.get_logger(__name__)`; `log.info("event_name", key=value)`. Snake_case
event names, ids instead of personal data, no `print`. Every request line carries
`request_id` (also returned as `X-Request-ID` and in problem bodies).

## 20. Decisions taken without the product owner (phase 2a)

- Module package names are provisional (`core`, `requests_comms`, `imports_master`,
  `staging_fulfilment`, `field_service`, `stock_inventory`); phase 2b may rename them.
- States are VARCHAR + CHECK (`str_enum`), not native PostgreSQL enums.
- Problem type URIs use `https://hangar.example.com/problems/<slug>`.
- No implicit commit per request; services call `commit()` explicitly.
- `GET /api/v1/jobs/{id}` reports procrastinate status only; results live in module tables.
- `/health` returns 200 with `status: "degraded"` when no worker heartbeat is seen, 503
  only when the database or job schema is unavailable.
- Until the first Alembic migration exists, `hangar migrate` falls back to `create_all`.
