# `h2_imports` — H2 Import & Master data

Imports (CSV/XLSX) of ITSM and partner exports, plus master data administration: articles,
regions and region rules, the VIP list and users.

## Tables (migration branch `h2`, revision `h2_0001_imports`)

| Table | Notes |
|---|---|
| `import_jobs` | one row per upload; `id` is `GENERATED BY DEFAULT AS IDENTITY` so the upload endpoint can reserve it (`nextval`) before the background job and the stored file reference it. Extra columns beyond SPEC §5.3: `job_warnings` (jsonb, API `jobLevelWarnings`) and `failure` (reason of status `failed`). |
| `import_job_errors` | one row per issue (error or warning) of a row; CHECK on `severity`. |

## Endpoints (API.md §5)

- `/imports`: `POST` (multipart upload → `202 JobAccepted`), `POST /detect`, `GET` (history),
  `GET /{id}`, `GET /{id}/errors`, `POST /{id}/actions/cancel`, `GET /{id}/file`,
  `GET /{id}/error-report`, `GET /templates`, `GET /templates/{type}/sample`,
  `POST /generate-sample` (demo mode).
- `/articles` (list, detail, create, patch, `actions/{activate|deactivate}`,
  `site-settings/{siteId}`), `/regions/{id}` (GET/PATCH), `/region-rules` (CRUD, `test`,
  `reapply`), `/vip-entries` (CRUD), `/users` (`GET/{id}`, `POST`, `PATCH`,
  `actions/{activate|deactivate|reset_password}`). `GET /users` and `GET /regions` are core.

## Import engine (`importing/`)

`reader.py` (UTF-8 CSV with delimiter detection / XLSX via fastexcel, header normalization) →
`formats.py` (the five column specifications, detection precedence) → `validate.py` (polars:
trim, placeholders → null, keys upper-cased, `missing_required` / `too_long` /
`invalid_format` / `duplicate_in_file` column-wise; per row: dates, emails, enums, zip, MAC,
phone and the packed `[Key: value]` columns via `packed.py`) → `processor.py` (chunks of 500,
one transaction per chunk, one SAVEPOINT per row, progress + issues + cancel check after
every chunk, post-processing, failed-row report, `import.summary`, `ImportFinished`).
`appliers/` hold the per-type logic; `runtime.py` has the worker runtime (own sessions) and
the single-session runtime used by tests.

All status changes go through core services with trigger `import`: SR/lease
`import_create`, `link_service_request` (`link_lease_returns`, also after lease imports —
RES #55), `mark_hardware_unavailable` (+ `hold_source = import`, RES #37), `cancel` (ITSM
`Cancelled`), lease `mark_probably_closed` and `reopen`; assets `receive`, `sync_in_use`,
`sync_collected` (create from ∅ allowed, RES #49). Region/campus via `apply_region` /
`apply_lease_campus`; items are re-synced only in `REGION_MUTABLE_STATUSES` (RES #29),
otherwise warning `items_locked`.

## Seed (order 20) and samples

Seven import jobs by Dana (SPEC §11.7) with stored uploads; issues computed with the real
parser plus catalogue/contact checks; story counts. `samples/*.csv` (repo root) are written by
`uv run python -m app.modules.h2_imports.samples` against a seeded database; the sample
endpoint builds the same files on the fly. Exporter: `import_jobs`, `import_job_errors`.

## Decisions taken without the product owner

- Uploads and error reports are kept without TTL. Core `files.cleanup` also skips any stored
  file a row still references (`import_jobs.file_id`, `error_report_file_id`).
- `import.summary` and `ImportFinished` are skipped for dry runs (nothing changed).
- `markMissingAsProbablyClosed` is skipped when the import was cancelled before the last chunk
  (the file was not fully read).
- Gender, MAC, phone, unknown ITSM state and invalid optional emails are warnings (value
  ignored / stored as given); procurement type and the contact email are errors.
- A failed row rolls back its SAVEPOINT and drops the after-commit callbacks it queued (no mail
  for rows that were not applied) — core `savepoint(session)`.
- `is_vip` of new records comes from `is_vip_user`; when a re-import changes a record's user,
  `recompute_vip` refreshes the flags. VIP flags never change status.
- Lease "late linking" picks the most recently imported non-terminal SR naming the tag.
- Users: own role / own deactivation → `409`; demo personas keep their role (`409`) and their
  password (`409`, as specified). In demo mode they also cannot be deactivated (`409`): anyone
  can sign in as a persona on the public demo, so locking personas out would break it for all.
- Region rules with `deliveryType = parcel_to_pickup_point` need a pickup point on the region
  (`422 deliveryType`); a region PATCH that would leave pickup delivery without a pickup point
  is `422 pickupPoint`.
- Article `openDemand` is computed live with the §6.7 demand predicate (no dependency on H5's
  recalculation); `assetCount` excludes deactivated assets.
- Cancelling a queued import finishes its background job via the `finish_job` helper after
  commit; a running import is cancelled cooperatively through `import_jobs.cancel_requested`
  plus the core `request_cancel` helper (`background_jobs.cancel_requested`).
- New articles get one `article_site_settings` row per hub through the core
  `ensure_article_site_settings`; the seeder records its history with `record_job` and
  backdated `store_file(created_at=...)`.
